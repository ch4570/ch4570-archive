작업 사례

01

실제 영속성 컨텍스트에서 JPA 변경 감지 오류를 재현하고 약 200만 건을 보정했습니다

Mock 테스트에서 놓친 저장 오류를 실제 영속성 컨텍스트에서 재현했습니다. 보정 스크립트로 잘못 저장된 값을 바로잡아 저장 데이터를 다시 신뢰할 수 있게 했습니다.

  • 문제: Mock 테스트는 영속성 컨텍스트의 변경 감지와 저장 시점을 거치지 않아 오류가 드러나지 않았습니다.
  • 재현·보정: 실제 저장 환경에서 재현해 원인을 확인하고, 오류 데이터 약 200만 건을 식별해 보정 스크립트로 바로잡았습니다.
  • 회귀 검증: 실제 저장 결과를 확인하는 테스트를 보강했습니다.
02

Drive 서비스의 CPU·미삭제 파일·테스트를 숫자로 확인했습니다

JANDI 드라이브 기능을 제공하는 마이크로서비스입니다.

  • Live RDS CPU가 99%까지 오른 문제를 리소스를 늘리기 전에 원인부터 분석해 평균 3%로 낮췄습니다.
  • S3에 지워지지 않고 남은 파일 60,325건을 찾아 삭제해 771.61 GB 점유를 해소했습니다.
  • 테스트 코드를 도입해 0개에서 300개+로 늘렸고, Spring Boot를 2.3.8에서 3.3.3으로 올렸습니다.
03

추천 피드 서빙 엔진은 느린 경로를 빼고 응답을 이어 갑니다

벡터 검색은 후보를 찾는 단계에 쓰고, 이후에는 접근성·신선도·열람 경험을 같은 기준으로 다시 평가합니다.

  • 조회 경로 9개를 병렬로 실행하고 경로별 500ms 타임아웃으로 늦은 경로만 제외했습니다.
  • 1차 500건 → 2차 100건 → 재정렬 → 20건 응답. 단계별 캐시로 다음 페이지 재계산을 줄이고 페이지 간 중복 노출을 막았습니다(개발 환경에서 확인).
  • Redis 캐시를 우회해도 첫 페이지를 계산해 응답하는 경로를 두었습니다.
04

멈춘 이벤트와 배치를 이어 실행하고 포인트 정합성을 확인했습니다

포인트·CPC 광고 플랫폼의 이벤트 복구와 배치입니다.

  • 발행 전에 멈춘 이벤트와 발행 뒤 업무 처리에서 실패한 이벤트를 나눠 6개 상태로 기록하고, 저장한 payload로 실패한 업무만 다시 실행합니다.
  • Kafka 내부 이벤트 9종에 복구 경로 8개를 두었고, 15분 넘게 멈춘 이벤트는 유형별로 묶어 Slack으로 알립니다.
  • 아카이브 테이블은 참조 순서대로 옮기고 중단되면 시작 ID부터 다시 실행합니다.
  • 같은 락 키나 예산을 공유하는 요청을 동시에 실행한 뒤 잔액·원장·후속 이벤트를 대조했습니다.
  • 60초 안에 클릭 정보 5개 키가 모두 같은 클릭이 다시 들어오면 포인트를 차감하지 않고 어뷰징 로그로 기록했습니다. 광고 노출 종료일 576건도 일괄 보정했습니다.

code-hub의 신청·검증·승인 흐름과 쓰기 API 접근 제어를 작업했습니다

다른 팀에서 인수인계받은 공통 코드 관리 플랫폼의 관리자 기능입니다. 2026.10 이후 작업은 공동 작업 브랜치에서 병합 전입니다.

  • 승인 직전에 다시 판정하고 승인 뒤 캐시를 갱신합니다. 새 테이블 없이 기존 상세 테이블을 다시 쓰는 구조로 설계했습니다.
  • 관리자 키를 DB 해시로 옮기고 경로 기반으로 호출자를 가르며, 클라이언트별 허용 경로를 화면에서 고치고 이력을 남기는 기능을 작업했습니다.
  • ElastiCache 패치로 Primary가 바뀌어도 쓰기가 막히지 않도록 접속 방식을 Primary·reader endpoint로 바꾸는 작업을 했습니다.
